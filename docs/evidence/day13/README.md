# Day 13 recognition-interface screenshots

These 1440×1100 PNG screenshots are browser-rendering evidence for the Day 13
Recognition workflow:

- `authorized.png` — authoritative `AUTHORIZED / ACTIVE_MATCH` result with
  OCR, confidence, crop, processing, evidence/log status, and reference;
- `unauthorized.png` — authoritative
  `UNAUTHORIZED / VEHICLE_NOT_FOUND` result;
- `manual-review.png` — authoritative
  `MANUAL_REVIEW / OCR_LOW_CONFIDENCE` result;
- `no-plate.png` — explicit no-plate outcome with no invented authorization
  decision;
- `invalid-file.png` — browser rejection of a non-JPEG/PNG selection before
  submission;
- `server-failure.png` — sanitized structured backend failure with correlation
  reference.

The screenshots were generated by
`frontend/tests/evidence/day13-recognition.spec.ts` using Playwright 1.62.1,
system-installed Chrome, the legal synthetic repository fixture, and
deterministic browser request interception for
`POST /api/recognition/analyze`. Interception exercises the production
frontend runtime parser and UI states but does not claim live detector/OCR,
database, storage, or authorization accuracy. The fixtures contain redacted
private-evidence metadata and no signed-access token, credential, private
filesystem path, or production bypass.

Regenerate from `frontend/`:

```powershell
npm.cmd run evidence:day13
```
